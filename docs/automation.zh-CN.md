# Agent Title Renamer Skill 自动化教程

[English](automation.md)

安装 Agent Title Renamer Skill 不会自动创建计划，也不会自行运行。自动化是宿主提供的独立能力；只有宿主暴露了所需的会话工具，Skill 才能真正执行标题修改。

## 先确定三件事

创建自动化前，请先选择：

1. **范围：** 当前项目、指定项目，或全部可访问项目。
2. **运行时间与时区：** 例如按你选择的时区，每天 09:00 和 21:00 各运行一次。
3. **模式：** 审阅或自动。

运行时区决定自动化何时触发；标题时区决定如何把 `createdAt` 转换成 `MMDD`。两者可以相同，但都应明确写出。

如果宿主支持“出现新会话时运行”这类事件触发，优先使用事件触发；否则使用固定周期。

## 审阅模式模板

希望每批都亲自确认时，使用：

```text
使用 $agent-title-renamer 检查 [准确范围] 中符合条件的会话。
把 createdAt 转换为 MMDD 时使用 [标题时区]。
以审阅模式生成完整的 Before/After 预览，然后停止。
绝不修改项目或工作区名称，也不修改标题以外的任何会话属性。
```

预览会出现在宿主显示的任务或运行记录中。打开同一个会话并明确回复确认即可，例如「确认」。每次计划运行都会生成自己的快照。

## 自动模式模板

只有确实需要无人值守改名时，才使用：

```text
对 [准确范围] 使用 $agent-title-renamer 自动模式。
这份保存的提示词明确授权本次运行无需另行确认即可应用标题修改。
把 createdAt 转换为 MMDD 时使用 [标题时区]。
逐项重新核对，只修改标题，验证每项结果，并报告已修改、已跳过或失败的条目。
不要绕过宿主的权限提示或访问控制。
绝不修改项目或工作区名称；绝不修改内容、归属、顺序、置顶或归档状态。
```

范围必须准确。只有当宿主能够安全枚举全部项目，并且你确实希望覆盖全部项目时，才使用“全部项目”。

## Codex 计划任务

在 Codex 中，用自然语言请求创建自动化，并让用户自行选择运行时区。例如：

```text
为 Agent Title Renamer Skill 创建一项周期自动化。创建前先让我选择运行日期、时间和时区，并询问标题日期应使用哪个时区。

保存以下提示词：
[粘贴上方其中一个模板，并填入准确范围]
```

如果处理本地项目，可以把自动化附着在名为“标题整理”的专用任务上，让预览和确认集中在一处。本地运行触发时，需要电脑保持可用、Codex 应用正在运行，并且本地项目可以访问。

创建后检查：

- 计划显示的是你选择的时区；
- 保存的提示词明确包含 `$agent-title-renamer`；
- 范围和模式写得清楚；
- 标题时区已经写明；
- 自动化附着在预期项目或任务上；
- 只有你主动选择时，才出现自动模式授权。

## Claude Code

Claude Code 可以加载这个 Skill，并生成规范化标题建议。配置随附的可选 Python SDK 适配器后，还能在每次运行的一个准确项目目录内，列出、重新核对、修改并验证本机持久化会话。跨项目和跨 worktree 的 SDK 清单仅用于只读发现，因此应按准确目录分别创建运行，不能合并成一份宽泛的修改计划。没有适配器时，原生 `/rename` 仍是当前会话的降级方案。

Claude 的周期任务（routines）或外部调度器可以重复运行保存的提示词；安装 Skill 或适配器本身不会创建计划。无人值守运行时，保存的提示词必须明确授权自动模式，适配器还会同时要求自动模式计划和匹配的执行开关。Claude 批量桥接仍处于 Beta，建议优先整理已经结束的会话。

这里仅覆盖本地 Claude Code 历史，不包括 Claude.ai、网页、移动端、另一台电脑，或没有持久化到本机的云端历史。不要通过修改 Claude 的内部 JSONL 文件实现自动化。

## 其他 Agent Skills 宿主

使用宿主自己的计划任务（scheduler）、钩子（hook）、周期任务（routine）或事件触发器。保存的提示词仍需明确：

- 准确范围；
- 运行时区；
- 标题时区；
- 审阅模式或明确授权的自动模式；
- 只修改标题；
- 修改前复核，修改后验证。

如果宿主不能列出、读取、重命名并验证目标条目，请使用仅预览模式。

## 修改或停止自动化

修改前先让宿主显示现有自动化，优先更新原计划，避免创建重复任务。暂停或删除时，请使用宿主公开支持的自动化控制方式。
